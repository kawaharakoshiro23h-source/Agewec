### ワークフロー説明（必須）

```
LangGraph の StateGraph で11工程を接続し、工程間に interrupt() による
人間承認ゲートを置いた半自律ワークフロー。人間の関与は各工程の
「承認 / 差し戻し（自然言語フィードバック）」のみで、成果物の生成は
すべてエージェントが行う。

[工程]
01 Executive Producer  テーマから制作ブリーフを策定
02 Creative Director   コンセプト・配色・エネルギー曲線・成功条件を定義
03 Writer Storyboard   8カット48秒の絵コンテ（今回は config で固定指定）
04 Asset Curator       285枚から各カットの素材を選定
                       （決定論的ランカー + LLMによる選定理由生成）
05 Director            カットごとのカメラワークと英語生成プロンプトを設計
05.5 Support Video Creator  モデル別の許容尺・解像度・費用を確定
06 Image→Video         Runway Dev API (hailuo3) で8カットを生成
07A Cut Visual QA      ffprobe で尺・解像度・コーデックを機械検査
07B Sequence QA        全カットの成果物実在と尺整合を検査
08 Post Production     FFmpeg で正規化・結合（クリップ音声は -an で除去）
09 Provenance          出典・判断ログ・技術レポートを出力

[設計上の要点]
- LLM は役割別のシステムプロンプト（Markdown 9本）で呼び分け、
  出力は Pydantic スキーマで検証。失敗時は修復リトライ。
- 生成プロンプトは英語、人間が読む項目は日本語、という言語ポリシーを明示。
- 状態は SqliteSaver に永続化し、中断・再開が可能。
- 送信前に「実課金累計 + 次回見積 ≦ 上限」を検査するコストガードを実装。
- 承認済みカットは approved_cut_ids で保護し、再課金を防止。
- 全判断を decision_log.jsonl に記録（人間/AIの別、差し戻し理由を含む）。
- 実行中の状態を監視するローカル Web UI を別途実装（読み取り専用）。

[実測]
- 動画生成: 14回 / US$12.45（Runway hailuo3）
- LLM: 累計 US$0.51（gpt-4o-mini）
- 最終出力: 1920x1080 / 24fps / 48秒

「北九州市のPR・観光振興目的」の範囲で使用。全素材の出典URL・取得日時・
SHA-256を provenance.json に記録。二次配布はしていない。
```
